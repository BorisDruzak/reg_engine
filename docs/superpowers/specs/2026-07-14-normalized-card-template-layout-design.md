# Нормализованный макет редактора шаблона карточки

## Цель

Сделать web-макет шаблона предсказуемым и читаемым: блоки идут вертикальным
списком во всю ширину, а новые поля сразу имеют удобный полный размер.

## Блоки

- Каждый блок web-макета всегда имеет `column=1`, `column_span=12` и занимает
  одну логическую строку в последовательном порядке.
- Блоки нельзя растягивать, сжимать или свободно перемещать по сетке.
- Единственное действие с расположением блока — перенос вверх/вниз в порядке
  списка. Оно пересчитывает последовательные строки без пустых областей.
- Открытие существующего макета нормализует его черновое представление:
  ширина каждого блока — 12 колонок, строки идут подряд. Нормализованная
  геометрия попадает на сервер только через уже существующее сохранение макета.
- Создание блока располагается после последнего блока. Действие
  `Вставить существующий блок` и его пустая область удаляются.

## Поля

- Существующие настройки размера и положения полей не меняются.
- Новое поле получает `column=1`, `column_span=12`, `row_span=1` и первую
  доступную строку внутри выбранного блока. Благодаря этому встроенный
  редактор поля не сжимается до узкой ячейки.

## Команды шаблона

- В раскрытую строку шаблона переносятся `Отменить`, `DOCX`, `PDF` и
  `Закрыть`; они сохраняют существующие обработчики, блокировку во время
  операции и доступность только для открытого шаблона.
- В заголовке `CardLayoutStudio` эти кнопки не отображаются. Индикатор
  сохранения остаётся доступным как статус, а не как отдельное действие.
- Переименование шаблона, архивирование, технический код и вкладки
  `Макет карточки / Печатная форма A4 / Предпросмотр` остаются без изменения.

## Границы реализации

- Без новых API, миграций и изменения схемы БД.
- Печатная форма A4 и её самостоятельная геометрия не нормализуются.
- Карточки, уже созданные по шаблону, не меняются.
- Российские подписи, текущие проверки прав и механизм сохранения макета
  используются без обхода backend API.

## Проверки

- Unit-тест нормализации блоков проверяет полную ширину и последовательные
  строки для криво сохранённого макета.
- Тест рендера подтверждает отсутствие управления изменением размера блока,
  нижнее создание блока и отсутствие вставки существующего блока.
- Тест `CardLayoutStudio` подтверждает, что новое поле получает ширину 12.
- Тест реестра подтверждает перенос `Отменить`, `DOCX`, `PDF` и `Закрыть` в
  раскрытую карточку шаблона.
- Focused Vitest, TypeScript, lint, production build и браузерная проверка
  выполняются перед развертыванием.
