# История изменений карточек и удержание аудита

## Цель

Дать системному администратору отдельную историю изменений каждой карточки с
безопасным сравнением значений, а также автоматически удалять устаревшие
аудиторские записи по двум разным срокам хранения.

## Границы

- История расположена в разделе `Аудит` как вторичная вкладка
  `История карточек`; в рабочем пространстве карточки новой вкладки нет.
- Читать общий аудит и историю карточек может только системный администратор.
- История карточки включает изменения самой карточки, её жизненного цикла,
  организации, публичного доступа, экземпляров блоков и значений полей.
- Запись значения поля содержит `было` и `стало`, код, название и тип поля.
- Для поля с `sensitivity_level`, отличным от `normal`, в diff сохраняется
  только признак изменения; значение до и после не сохраняются.
- Событие публичного редактирования сохраняет фактический источник
  `public_link`, идентификатор ссылки и отдельную атрибуцию пользователю,
  который создал ссылку. Оно не выдаёт создателя ссылки за фактического
  исполнителя ввода.
- События истории карточек хранятся 14 суток от `created_at`; прочие
  технические события хранятся 3 суток от `created_at`.
- Очистка выполняется ежедневно отдельным systemd timer и не зависит от
  входящих HTTP-запросов.

## Модель данных

`audit_events` получает nullable-колонки `card_id`, `attributed_user_id` и
`retention_class`.

- `card_id` связывает событие с карточкой и индексируется вместе с
  `created_at` для обратной ленты истории.
- `attributed_user_id` ссылается на пользователя, создавшего публичную ссылку;
  он заполняется только для событий, созданных через ссылку.
- `retention_class` имеет значения `card_history` и `technical` и индексируется
  вместе с `created_at`. Срок не хранится отдельной датой: он однозначно
  вычисляется при очистке как 14 дней для `card_history` и 3 дня для
  `technical`.

Миграция относит существующие строки к `technical`: прежние строки не содержат
полного безопасного diff и не должны смешиваться с новой историей карточек.
Новые карточечные события получают `card_history` при записи. Это означает, что
сразу после включения политики прежний технический журнал будет очищен по
трёхдневному сроку.

## Diff значений

`CardService` формирует сериализуемый снимок значения до изменения и после
изменения. Снимок включает `field_id`, `field_code`, `field_label`,
`field_type` и `value`. Для чувствительного поля вместо `value` записывается
`{"redacted": true, "changed": true}`. Это правило применяется и к
административной, и к публичной записи.

Уже существующие карточечные аудиты сохраняют свои метаданные, но получают
`card_id` и `card_history` для единой ленты.

## API и интерфейс

Добавляется системно-администраторский маршрут списка истории по `card_id` с
пагинацией/лимитом и обратной сортировкой. Ответ включает отображаемое имя
атрибутированного пользователя, когда событие пришло через публичную ссылку.

В разделе `Аудит` остаётся вкладка общего технического журнала. Вкладка
`История карточек` содержит выбор карточки из доступных системному
администратору, ленту событий, исполнителя/создателя ссылки, источник, время
и разворачиваемый diff `Было` / `Стало`.

## Очистка и эксплуатация

`AuditRetentionService` удаляет только записи, которые старше срока своего
`retention_class`, и возвращает количество удалённых строк. Команда backend CLI
запускает сервис один раз и используется systemd oneshot service с ежедневным
timer (`Persistent=true`). Установка timer включается в проектные скрипты
развёртывания; она не требует секретов и не меняет данные карточек.

## Проверки

- сервисные тесты: обычный и чувствительный diff, атрибуция создателя ссылки,
  классификация и удаление по сроку;
- API-тесты: только суперпользователь читает историю нужной карточки;
- frontend-тесты: вкладка находится только в `Аудит`, не в карточке, и
  отображает корректный diff/атрибуцию;
- миграция проходит upgrade/downgrade на disposable PostgreSQL `_test`;
- после развёртывания timer активен, API здоров, а ручной dry-run/проверка
  количества просроченных записей не затрагивает непросроченные события.
