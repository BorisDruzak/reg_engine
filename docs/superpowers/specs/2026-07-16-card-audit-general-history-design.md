# Общая история карточек: дизайн

## Цель

Сделать вкладку `История карточек` полезным общим журналом карточечных
событий для системного администратора. Журнал должен отображать создание,
обновление, архивирование и другие относящиеся к карточке события, позволять
быстро перейти к истории конкретной карточки и не раскрывать значения
чувствительных полей.

## Границы и доступ

- История карточек остаётся доступной только системному администратору.
- Источник данных — только события с `retention_class=card_history`; правила
  хранения не меняются: 14 дней.
- Технический аудит остаётся отдельной вкладкой и хранится 3 дня.
- В общий журнал попадают активные и архивированные карточки, но состояние
  карточки управляется фильтром. Значение по умолчанию — только активные.
- Уже принятая атрибуция изменений через публичную ссылку сохраняется: в
  журнале показываются сама публичная ссылка и пользователь, создавший её.

## Экран истории

Вкладка по умолчанию открывает общий журнал активных карточек. Над журналом
расположены три фильтра:

1. `Статус карточки`: `Активные` (по умолчанию), `Архивные`, `Все`.
2. `Карточка`: `Все карточки` (по умолчанию) либо конкретная карточка.
3. `Изменение выполнил`: `Все исполнители` (по умолчанию) либо пользователь.

Кнопка `Сбросить фильтры` возвращает к общему журналу активных карточек:
очищает фильтры карточки и исполнителя и устанавливает статус `Активные`.

В общем режиме строки сгруппированы по карточке. Группа содержит название
карточки, её состояние и относящиеся к ней события, отсортированные от новых
к старым. Группы отсортированы по последнему событию. Название карточки в
заголовке группы — кнопка: нажатие выбирает эту карточку в фильтре и сразу
показывает только её историю. Это позволяет перейти от создания карточки к
последующим изменениям без поиска вручную.

В режиме выбранной карточки та же таблица показывает только её события; при
этом фильтры статуса и исполнителя по-прежнему применяются. Архивированная
карточка отображается при статусе `Архивные` или `Все`.

## Отображение изменений

Для событий значений полей используются существующие безопасные снимки
`field` / `value`; ссылки преобразуются в отображаемые названия. Для
составных снимков карточки или публичного доступа API возвращает
нормализованный список изменённых свойств с русскими названиями и отдельными
значениями `было` и `стало`. Интерфейс отображает эти значения, а не общую
заглушку `Изменено`.

- Создание и архивирование показываются как самостоятельные события, без
  выдуманного значения «было».
- Для публичного доступа показываются только изменившиеся настройки карточки
  и полей, с названиями полей и понятными значениями `Включено` / `Отключено`.
- Для карточки показываются только фактически изменившиеся свойства, например
  название, подразделение и режимы публичного доступа.
- У чувствительных полей значения остаются `Скрыто`; нормализация не обходит
  `sensitivity_level` и не возвращает исходное значение.
- Неподдерживаемые старые технические снимки не показываются как JSON и не
  маскируются парой `Изменено → Изменено`: они получают безопасное читаемое
  описание события, если точный исторический diff восстановить невозможно.

## API и данные

`GET /api/v1/audit-events` для `scope=card_history` перестаёт требовать
`card_id`. Необязательные параметры:

- `card_id` — ограничивает журнал одной карточкой;
- `card_status` — `active`, `archived` или `all`;
- `actor_user_id` — исполнитель; для изменений через публичную ссылку
  сопоставляется с пользователем, которому событие атрибутировано.

Запрос по-прежнему проверяет права системного администратора на сервере.
Статус фильтруется через связанные карточки, включая архивированные записи.
`lifecycle_sync` остаётся исключённым из истории, так как это техническое
следствие основного пользовательского события.

Ответ для карточечной истории получает сведения о карточке, достаточные для
группировки и подписи, и нормализованные безопасные отображаемые различия.
Никакие сырые значения чувствительных полей, UUID справочников или внутренние
JSON-снимки в браузер не возвращаются как отображаемые значения.

## Проверки

Покрыть тестами:

- общий журнал без `card_id`, включая создание и архивирование;
- фильтры по активным, архивным и всем карточкам;
- фильтр исполнителя, в том числе атрибутированного создателя публичной
  ссылки;
- сохранение запрета для не-системного администратора;
- отображение реальных `было` / `стало` для снимков карточки и публичного
  доступа без JSON и без `Изменено → Изменено`;
- группировку на экране, переход нажатием на карточку и сброс фильтров.
