# Inline-редактирование названия шаблона карточки

## Цель

Позволить администратору переименовать шаблон карточки прямо в раскрытом
редакторе шаблона, не добавляя отдельную кнопку редактирования и не меняя
логику архивирования.

## Поведение

- Карточка шаблона в списке по-прежнему открывает его редактор.
- Только у открытого шаблона заголовок редактора доступен для клика.
- Клик по названию заменяет его полем ввода с исходным значением и действиями
  `Сохранить` и `Отменить`.
- `Сохранить` отправляет существующий `PATCH /api/v1/card-templates/{id}`
  только с изменённым `name`, затем обновляет кэш реестра и заголовок.
- `Отменить` возвращает обычный заголовок без запроса и без изменения макета.
- Пустое или состоящее только из пробелов название не отправляется; применяется
  существующее русскоязычное сообщение о незаполненных обязательных полях.
- Пока сохраняется имя, кнопка сохранения блокируется, а повторный клик по
  заголовку не открывает вторую форму.

## Архивирование

- Шаблон не удаляется физически. Кнопка `В архив` сохраняет существующее
  подтверждённое soft-archive поведение: шаблон становится недоступным для
  нового выбора, а уже созданные карточки и их история остаются читаемыми.
- Встроенное переименование не изменяет поля, блоки, макет, технический код,
  статус или правила архивации.

## Реализация

- Изменяется только клиентская композиция `RegistriesAndSchema` и её
  компонентный тест. API, схема БД и сервисы уже поддерживают частичное
  обновление имени и не требуют изменений.
- Состояние переименования локально для раскрытого шаблона: идентификатор,
  черновое имя и ошибка мутации.

## Проверки

- Компонентный тест открывает шаблон, включает редактирование кликом по
  названию, меняет имя и проверяет единственный PATCH с `{ name }`.
- Отдельный тест проверяет отмену без PATCH и недоступность встроенного
  редактирования у нераскрытого шаблона.
- Запускаются focused Vitest, TypeScript и production build; затем проводится
  браузерная проверка без отправки побочных изменений.

## Границы

- Не добавлять отдельную кнопку редактирования.
- Не показывать технический код как часть встроенного редактора.
- Не добавлять физическое удаление или новые API-маршруты.
