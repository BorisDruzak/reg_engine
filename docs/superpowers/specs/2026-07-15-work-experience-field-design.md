# Тип поля «Стаж работы»

**Дата:** 2026-07-15  
**Статус:** согласованный дизайн, ожидает просмотра спецификации

## Цель

Добавить в конструктор схем новый динамический тип поля `work_experience`.
Пользователь заполняет одно поле тремя числами: дни, месяцы и годы. Система
сразу показывает русские слова в правильной форме и далее сама пересчитывает
стаж по календарной дате сервера.

## Границы

- Это одно поле схемы и один редактор, а не три независимых поля карточки.
- Пользовательские экран, API-ответы, документы и XLSX-выгрузки показывают
  только стаж в фиксированном порядке: `дни → месяцы → годы`.
- Техническая дата используется только на сервере для расчётов и никогда не
  выводится как значение поля.
- Поле остаётся обычным динамическим полем: права доступа, аудит и настройки
  публичного редактирования применяются по существующим правилам.

## Ввод и отображение

Редактор содержит три неотрицательных целочисленных ввода в порядке `дни`,
`месяцы`, `годы`. После изменения любого числа строка результата меняется без
отдельной кнопки, например: `16 дней 3 месяца 9 лет`.

Формы слов для каждого числа `N`:

1. Если `N % 100` находится в диапазоне от 11 до 19, используется форма
   множественного числа: `дней`, `месяцев`, `лет`.
2. Иначе при `N % 10 == 1` используется `день`, `месяц`, `год`.
3. Иначе при `N % 10` от 2 до 4 используется `дня`, `месяца`, `года`.
4. Во всех прочих случаях используется `дней`, `месяцев`, `лет`.

При сохранении сервер принимает любые неотрицательные целые числа. Сразу после
сохранения и на каждом следующем чтении он возвращает нормализованный
календарный результат. Если два разложения дают одну и ту же опорную дату
(например, около конца месяца), исходное разложение не сохраняется. Поэтому
вводу не требуется отдельная кнопка преобразования и не возникает накопление
ошибок от ручного увеличения счётчика.

## Хранение и расчёт

В `field_values.value_json` хранится только внутренняя опорная дата
`anchor_date` в ISO-формате. При первом сохранении сервер вычитает введённые
годы, месяцы и дни из своей текущей календарной даты и получает эту дату. При
ручной правке стажа опорная дата пересчитывается тем же способом.

При каждом чтении значения сервер вычисляет календарную разницу между
`anchor_date` и текущей датой сервера, возвращает числа `days`, `months`,
`years` и сформированную строку `display`. Серверная дата является
единственным источником времени: часы браузера и ПК пользователя не участвуют
в расчёте. Ежедневный фоновый процесс и ежедневные записи в БД не нужны, так
что перезапуск сервера не влияет на стаж.

Ни API-ответы для пользовательских экранов, ни выгрузки не раскрывают
`anchor_date`. XLSX и документные рендереры используют `display` в том же
формате `дни → месяцы → годы`.

## Интеграция

- Зарегистрировать `work_experience` в серверном и клиентском списках типов,
  добавить миграцию ограничения `form_fields.field_type`.
- Сохранение и чтение реализовать через существующий JSON-слот значения поля,
  не добавляя бизнес-колонок в модель карточки.
- Подключить единый редактор к созданию карточки, обычному заполнению,
  публичному заполнению и карточному layout-рендереру.
- Подключить единый серверный форматтер к заполненной карточке, XLSX-обмену и
  документным представлениям.

## Ошибки и тесты

Сервер отвергает отрицательные, дробные, строковые и неполные значения с
понятным русским сообщением. Тесты покрывают склонение на значениях 0, 1, 2,
4, 5, 11, 12, 14, 19, 21, 22 и 25; календарный переход на следующий день;
повторное ручное сохранение; отсутствие зависимости от времени браузера;
карточку, публичную ссылку, API и XLSX-выгрузку. Отдельно проверяется, что
техническая дата не попадает в пользовательские ответы и экспорт.
