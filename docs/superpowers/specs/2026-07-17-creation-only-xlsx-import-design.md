# Первичный XLSX-импорт карточек и пополнение глобальных справочников

## Статус

Согласованный проектный контракт. Документ описывает следующий этап XLSX-
импорта; реализации в нём нет.

## Цель

Сделать предсказуемое создание новых карточек из фиксированного XLSX-шаблона
в двух вариантах:

1. импорт внешней выгрузки с пополнением глобальных справочников;
2. ручное заполнение с обязательным выбором только существующих значений.

Оба варианта используют существующие динамические `form_fields`, шаблоны
карточек, типизированные `field_values`, сервисы карточек и серверный RBAC.
Они не добавляют предметных полей или таблиц для конкретной области.

## Не входит в объём

- поиск, обновление, перенос, архивирование или иное изменение существующих
  карточек;
- `upsert`, внешний ключ карточки и сверка отсутствующих строк;
- импорт `multi_select`, повторяемых блоков, файлов, JSON и ссылок на
  карточки, пользователей или реестры;
- создание значений в организационных, иерархических или иных неглобальных
  справочниках;
- Excel-макросы и бинарные вложения.

## Общий контракт XLSX

Файл создаётся для одного активного шаблона карточки и фиксированного набора
поддерживаемых полей этого шаблона. Сервер сверяет скрытую конфигурацию,
актуальную схему, текущий доступ и заголовки; доверять данным Excel как
авторитетному источнику нельзя.

Видимые системные колонки:

- `№ п/п` — только порядковая подсказка, не идентификатор;
- `Название карточки` — значение `cards.display_name`, с подписью из
  `registries.card_title_label`;
- `Организация` — только если выбрана видимая колонка организации.

Поддерживаются `text`, `number`, `date`, `datetime`, `bool`, `select`,
`organization_ref`, `org_unit_ref` и `work_experience`. Выбор доступных полей
также учитывает `is_exportable`. `multi_select` остаётся активным типом
схемы, но отображается в XLSX как неподдерживаемый с объяснением.

Текст, числа и даты проходят тот же серверный преобразователь и валидатор,
что и обычное редактирование карточки. Пустая обязательная ячейка не является
ошибкой первичного импорта: карточка остаётся `draft`. Если все обязательные
и обязательные при публикации поля заполнены, обычная синхронизация жизненного
цикла переводит карточку в `active`.

## Режим 1: создание карточек и пополнение глобальных справочников

Этот режим предназначен для файлов, экспортированных сторонней системой.
Колонки полей `select` содержат обычный текст и не получают строгого Excel
ограничения: автор файла может прислать значение, которого ещё нет в
справочнике.

Режим доступен только когда поле:

- имеет тип `select`;
- настроено на `reference_list`;
- использует активный глобальный плоский справочник;
- доступно пользователю для чтения и редактирования справочника.

Для значения из ячейки сервер строит ключ сопоставления: Unicode NFKC,
`strip`, замена последовательностей пробельных символов одним пробелом и
`casefold`. Нормализация применяется только к сравнению, не к сохранённой
подписи.

- Один активный элемент с таким ключом: использовать существующий элемент.
- Ноль элементов: показать создание в preview; при commit создать
  `ReferenceItem` в этом глобальном справочнике и использовать его.
- Два и более элемента: считать строку ошибочной и не выбирать один
  произвольно.

Новая подпись сохраняется как первое очищенное пользовательское написание.
Сервер генерирует технический `code` по детерминированному хешу
нормализованного значения с безопасным разрешением крайне маловероятной
коллизии. Технический код не выводится в основную ячейку XLSX.

Preview отдельно возвращает новые карточки, новые элементы справочников и
ошибки по строкам. Все новые элементы и карточки создаются одной транзакцией:
некорректный файл не оставляет частично созданных справочников. Параллельное
создание одного нормализованного значения должно быть защищено уникальным
техническим кодом и повторным чтением после конфликта уникальности.

Для commit требуются права на управление карточками в целевой организации и
право редактирования каждого затрагиваемого глобального справочника.

## Режим 2: строгое создание карточек

Этот режим предназначен для ручного заполнения официального шаблона.
Колонки `select` получают Excel Data Validation с выпадающим списком и
`Stop`-ошибкой. Значение вне списка становится ошибкой preview и не создаёт
новых элементов справочника. Сервер повторяет проверку независимо от Excel.

В видимых списках используется пользовательская подпись. Если подписи
неоднозначны, шаблон добавляет технический код только к конфликтующим
вариантам. Привязка на сервере выполняется к идентификатору проверенного
элемента, а не к произвольной подписи.

## Стаж

Одно динамическое поле `work_experience` разворачивается в три колонки:

- `<поле> — дни`;
- `<поле> — месяцы`;
- `<поле> — годы`.

Если заполнена хотя бы одна колонка, все три обязательны и проходят
целочисленную доменную валидацию. Три пустые колонки означают отсутствие
значения. Сервер собирает их в одно существующее значение `work_experience`,
а не в три предметных поля.

Параметр файла `Дата актуальности стажа` применяется ко всему пакету и по
умолчанию равен дате импорта. Он определяет внутреннюю опорную дату, из
которой затем рассчитывается отображаемый стаж.

## Безопасность и надёжность

- Ограничивать не только размер ZIP-файла и число строк, но и число листов,
  столбцов, ячеек, распакованный объём и размер shared strings до полной
  обработки книги.
- Отклонять формульные ячейки при импорте. При экспорте экранировать строки,
  которые Excel интерпретирует как формулы.
- Форматировать идентификаторы и текстовые колонки как текст, чтобы Excel не
  терял ведущие нули.
- Использовать единый явный контракт часового пояса для `datetime`.
- Не создавать элементы в архивных, неактивных, иерархических или
  организационных справочниках.
- Все create-действия для карточек, значений и элементов справочников пишут
  существующие аудиторские события; успешный пакет дополнительно пишет
  агрегированное `import_commit`-событие с режимом импорта и счётчиками.

## UX и ошибки

В настройке XLSX пользователь выбирает один из двух режимов. Интерфейс
явно показывает, какие `select`-поля способны пополнять глобальный
справочник, а какие несовместимы с этим режимом. Для режима пополнения
предпросмотр содержит отдельный блок «Будут добавлены в справочники» с
полем, справочником, исходной подписью и числом использований.

Ошибки должны быть русскими и указывать номер строки и заголовок колонки.
Примеры: «в справочнике найдено несколько одинаковых значений», «справочник
не является глобальным плоским», «нет права редактировать справочник»,
«значение отсутствует в разрешённом списке».

## Проверки

- создание карточки с отдельным названием;
- неполная обязательная строка создаёт только черновик;
- режим пополнения повторно использует одно найденное значение независимо от
  регистра и крайних пробелов;
- режим пополнения создаёт одно новое значение, если оно встречается в
  нескольких строках;
- неоднозначное совпадение останавливает строку;
- отсутствие права редактировать глобальный справочник не допускает commit;
- строгий режим отвергает неизвестное значение;
- `multi_select`, иерархический и организационный справочники недоступны в
  режиме пополнения;
- три колонки стажа собираются в одно значение с общей датой актуальности;
- неверная частичная группа стажа, формула, превышение лимитов и изменённая
  схема файла не создают данных;
- атомарный rollback проверяет, что после ошибки нет ни карточек, ни новых
  элементов справочников;
- аудит содержит режим, число созданных карточек и число созданных значений.
