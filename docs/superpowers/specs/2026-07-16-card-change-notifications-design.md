# Уведомления об изменениях карточек

## Цель

Добавить внутренние персональные уведомления об изменениях карточек. Пользователь
подписывается на конкретную карточку и получает безопасное, понятное уведомление
о чужих изменениях. Создатель публичной ссылки может отдельно включить
уведомления о действиях, совершённых через созданную им ссылку.

Уведомления доступны только внутри веб-интерфейса: внешние каналы (email,
мессенджеры и push) не входят в данный этап.

## Пользовательский сценарий

1. У пользователя в верхней панели рядом с профилем есть кнопка-колокольчик с
   числом непрочитанных уведомлений.
2. Нажатие открывает компактную панель поверх текущей страницы. Переход со
   страницы не требуется.
3. Строка уведомления содержит карточку, исполнителя, изменённое поле, безопасные
   значения `было` и `стало`, а также время события. Нажатие открывает карточку и
   отмечает уведомление прочитанным.
4. Панель поддерживает действие `Отметить все прочитанными` и русское пустое
   состояние `Новых уведомлений нет`.
5. В доступной пользователю карточке есть переключатель `Уведомлять об
   изменениях` / `Не уведомлять`. Подписка персональная и не меняет настройки
   других пользователей.
6. В управлении каждой публичной ссылкой её создатель видит отдельный
   переключатель уведомлений о действиях через эту ссылку.

## Правила формирования

- Источником служат безопасные события истории карточек, а не необработанный
  `audit_events.diff`.
- Уведомление создаётся только при реальном изменении карточки или её значения.
  Технические события жизненного цикла и служебные JSON-снимки не становятся
  пользовательскими уведомлениями.
- Одна операция сохранения, меняющая несколько полей, создаёт одно уведомление с
  перечнем безопасных изменений, а не набор одинаковых уведомлений.
- Создатель подписки не получает уведомление о собственном изменении.
- Для действия через публичную ссылку исполнителем считается создатель этой
  ссылки, как и в истории карточки. Поэтому он не получает уведомление о
  собственном действии по ссылке.
- Подписка на карточку охватывает её пользовательские изменения независимо от
  способа их внесения. Подписка на публичную ссылку охватывает только изменения,
  совершённые через данную ссылку.
- Если один пользователь одновременно подписан на карточку и на публичную
  ссылку, одно изменение через эту ссылку даёт ему только одно уведомление.

## Данные и доступ

Нужны три изолированные сущности:

- персональная подписка пользователя на карточку;
- персональная подписка создателя на публичную ссылку;
- персональное уведомление с ссылкой на карточку/событие, подготовленным
  безопасным содержимым, датой создания и датой прочтения.

Уникальные ограничения не позволяют создать дублирующую подписку. Подписка на
публичную ссылку может создаваться и изменяться только её создателем. Подписка
на карточку доступна только пользователю, который имеет право видеть карточку.

При выдаче уведомлений сервер повторно проверяет доступ к карточке. Потерявший
доступ пользователь не получает её название, значения или ссылку на карточку,
даже если уведомление было создано раньше.

Содержимое уведомления использует те же правила маскирования и
`sensitivity_level`, что и история карточек. В базу уведомлений не копируются
сырые JSON-диффы, технические идентификаторы, хэши, токены или значения, которые
пользователь не вправе видеть.

## Хранение

Уведомления карточек хранятся 14 дней. Очистка использует тот же срок, что и
история карточек. Обычный технический аудит остаётся с отдельным сроком в 3 дня
и не используется как пользовательский список уведомлений.

## API и интерфейс

API предоставляет:

- чтение списка уведомлений и количества непрочитанных;
- отметку одного уведомления прочитанным и отметку всех прочитанными;
- чтение и переключение личной подписки на карточку;
- чтение и переключение подписки создателя на публичную ссылку.

Все проверки полномочий выполняются на backend. Интерфейс отображает колокольчик
в верхней панели, панель уведомлений, переключатель на карточке и переключатель
в управлении публичной ссылкой. Интерфейс не получает и не интерпретирует сырые
аудит-диффы.

## Проверка

Покрыть тестами:

- включение, выключение и уникальность каждой подписки;
- создание уведомления о чужом изменении карточки;
- отсутствие уведомления о собственном изменении;
- уведомления для действий через публичную ссылку и исключение её создателя;
- объединение нескольких изменений одной операции в одно уведомление;
- дедупликацию пересекающихся подписок;
- доступ, потерю доступа, прочтение, массовую отметку прочитанными и очистку
  уведомлений старше 14 дней;
- видимый интерфейс колокольчика, панели, карточного переключателя и
  переключателя публичной ссылки.

## Вне рамок

- email, мессенджеры, браузерные push-уведомления и фоновые внешние доставки;
- уведомления о техническом аудите;
- уведомления о собственных изменениях;
- произвольные глобальные подписки на все карточки.
