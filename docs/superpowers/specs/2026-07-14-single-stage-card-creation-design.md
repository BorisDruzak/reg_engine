# Одноэтапное создание карточки

## Цель

Заменить двухэтапный сценарий, в котором карточка создаётся до начала
заполнения, на один экран создания. Пользователь выбирает контекст карточки и
сразу заполняет поля выбранного шаблона; в базе не появляется пустая карточка.

## Экран

Вкладка `Создать карточку` остаётся отдельной рабочей вкладкой, но содержит
одну форму без перехода на другой экран или обновления страницы.

Верхний статичный блок содержит:

- организацию;
- шаблон карточки;
- необязательное наименование карточки.

Если доступен ровно один активный шаблон, он выбирается автоматически. Если
наименование не указано, используется название шаблона, как и в существующем
контракте создания карточки.

После выбора шаблона клиент запрашивает его структуру и макет. Ниже статичного
блока сразу отображаются блоки и поля этого шаблона. Перезагрузка страницы не
требуется. При смене шаблона после ввода значений пользователь подтверждает
сброс несохранённых значений; затем показывается структура нового шаблона.

## Сохранение и жизненный цикл

До первого непустого значения динамического поля карточка не создаётся и не
появляется в списке. Организация и шаблон сами по себе не создают черновик.

Первое непустое значение отправляется новым атомарным административным
сценарием первого сохранения. В одной транзакции он:

1. проверяет доступ пользователя к выбранной организации и шаблону;
2. создаёт карточку со статусом `draft`;
3. записывает первое значение;
4. создаёт аудит создания карточки и изменения значения;
5. синхронизирует жизненный цикл по существующим правилам обязательности.

После получения идентификатора карточки клиент продолжает использовать
существующее пакетное сохранение полей с задержкой. Когда заполнены все поля с
режимами `required` или `required_on_publish`, существующая синхронизация
переводит карточку в статус `active`. Необязательные поля не удерживают
карточку в черновике и могут быть заполнены позже.

При ошибке первого сохранения введённые значения остаются в форме, карточка не
создаётся, а пользователь получает русскоязычное сообщение. Повторный ввод
или сохранение повторяет один атомарный запрос; пустые карточки не остаются.

## Границы и совместимость

- Существующие API создания карточки, публичные ссылки, импорт и открытые
  карточки не меняют поведение.
- Новый endpoint предназначен только для административного одноэтапного
  сценария и использует те же проверки прав, валидацию типизированных полей и
  аудит, что и обычное сохранение значений.
- Структура карточки всегда берётся из выбранного шаблона. Бизнес-поля не
  добавляются в код как фиксированные колонки.
- Настройки публичного доступа, вложения и документы остаются доступны после
  первого сохранения, когда карточка уже существует.

## Проверка

Автотесты должны подтвердить:

1. выбор организации и шаблона без ввода не создаёт карточку;
2. один непустой ввод атомарно создаёт черновик с первым значением;
3. заполнение всех обязательных полей переводит карточку в `active`;
4. динамическая смена шаблона обновляет видимые блоки без перезагрузки;
5. единственный шаблон выбирается автоматически;
6. неудачное первое сохранение не создаёт карточку и сохраняет данные формы.
