# Codex Workflow

## Start Each Task

1. Read `AGENTS.md`.
2. Read `PLANS.md`.
3. For architecture or foundation work, read `docs/PROJECT_MAP.md` and `docs/ARCHITECTURE.md`.
4. Run `git status --short --branch`.
5. Inspect existing scripts before editing `scripts/*.ps1`.

## During Work

- Keep changes scoped to the requested task.
- Do not implement registry business logic during foundation work.
- Add tests before behavior where practical.
- Prefer project scripts over ad hoc command sequences.
- Update docs when changing commands, layout, or architecture.

## Checks

Use these commands before handoff:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check.ps1
powershell -ExecutionPolicy Bypass -File scripts/server-check.ps1
```

Use narrower checks while iterating:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/test.ps1
powershell -ExecutionPolicy Bypass -File scripts/lint.ps1
powershell -ExecutionPolicy Bypass -File scripts/typecheck.ps1
```

## Updating PLANS.md

- Mark tasks complete only after the corresponding check passes.
- Record known limitations.
- Add the next recommended phase.

## Avoiding Large Unreviewable Changes

- Group changes by backend, frontend, scripts, docs, or CI.
- Keep generated files out of commits unless they are lockfiles or docs generated by project scripts.
- Do not combine foundation work with business CRUD or schema implementation.
